# One-row Outlook app-only conversion runner (code only; production HOLD)

`cmd/outlook-convert` wraps the existing exact-four `email.Service.ConvertOutlookAppOnly` and repository CAS. This is **not** authorization to run it in production. It performs no activation, send, worker load, rollback or broad migration. `--help`, `--version`, missing/unknown arguments and `--dry-run` have no DB, Graph, GPG or write side effects. The CLI's dry-run is only a local permit parse, **not** a live-stage rehearsal. The excluded fifth UUID is rejected as target and privately fingerprinted before/after conversion.

Release gate: independent reviewer inspects the precise source and image build, verifies tenant-scoped app grant plus Exchange scope restriction, encrypted escrow of this row, no-send window, target dispatch fence, pending/in-flight drain, and an isolated staging rehearsal (including a CAS conflict). Only then may the reviewer sign an expiring target-specific permit with a trusted GPG key. Do not infer those conditions from this CLI or its tests. Production execution and rollback require separate authorization.

1. Build an isolated binary with `-ldflags '-X main.sourceSHA256=<64-char reviewed-source-digest> -X main.trustedReviewerFingerprint=<40-char authorized-GPG-fingerprint> -X main.version=<release>'`. The build pipeline must independently attest the source tree, compiled binary SHA-256, deployed image digest and runtime image identity. `WARMBLY_IMAGE_DIGEST` is an attestation input, **not proof of the actual image by itself**; reviewer must verify the deployed image ID out of band. Missing provenance prevents `--execute`. Do not attempt to embed the eventual image digest into the binary (self-reference).
2. Before signing, obtain a private GPG-encrypted JSON preimage: `{"account": <row_to_json(ea)>, "oauth": <row_to_json(o)>}` for the **one** target. Preserve the exact raw two rows including ciphertext and expiry; never put them in tickets, shell arguments, stdout or PR. Seal the encrypted file, record its SHA-256, the exact PostgreSQL credential version `md5(refresh_token || ':' || access_token || ':' || expires_at::text)`, and custody receipt. No plaintext temporary file is created by the runner.
3. Reviewer binds SHA-256 of exact raw grant/fence JSON and escrow ciphertext to a strict permit JSON. Fields: `target_id`, `owner_id`, `org_id`, `worker_id`, `tenant_id`, `email`, `app_id`, `credential_version`, `source_sha256`, `image_digest` (`sha256:<hex>`), `binary_sha256`, `config_sha256`, `escrow_sha256`, `grant_evidence_sha256`, `fence_evidence_sha256`, `reviewer`, `reviewer_fingerprint`, `reviewed_at`, `expires_at`, `no_send_from`, `no_send_until`. Times are RFC3339, expiry no more than 24h from review and covered by no-send window. `config_sha256` is SHA-256 of JSON string array `[PRIMARY_DB,BOX_OUTLOOK_CLIENT_ID,BOX_OUTLOOK_CLIENT_SECRET,BOX_OUTLOOK_TENANT_ID]` using Go `encoding/json` formatting; generate in a protected environment and never publish this sensitive digest or its preimage. Reviewer signs the exact permit file with a detached GPG signature. Keep signature, keyring and approval/hash receipt private; caller-provided `--permit-sha256` alone is not approval.
4. `grant-evidence` JSON requires exact `target_id`, `tenant_id`, `app_id`, `email`, `mail_read_write:true`, `mail_send:true`, `restriction_effective:true`, `observed_at`. `fence-evidence` JSON requires exact `target_id`, `dispatch_fenced:true`, `broker_pending:0`, `worker_in_flight:0`, `observed_at`, `fence_until`. Both observations must be less than five minutes old, neither future-dated, and fence must outlast permit. They are *reviewer-attested external observations*, not direct Graph/broker verification by the CLI. The reviewer must inspect the underlying raw service/admin evidence rather than accepting self-asserted JSON. Keep the fence enforced throughout preflight, CAS and readback.
5. Local syntax-only check: `outlook-convert --dry-run --target "$TARGET" --permit "$PERMIT" --permit-sha256 "$APPROVED_PERMIT_HASH"`. A success explicitly says `production HOLD`. Separately authorized execution: `outlook-convert --execute --target "$TARGET" --permit "$PERMIT" --permit-sha256 "$APPROVED_PERMIT_HASH" --permit-signature "$SIGNATURE" --reviewer-keyring "$KEYRING" --escrow "$ENCRYPTED_ESCROW" --grant-evidence "$GRANT" --fence-evidence "$FENCE" --receipt "$NEW_PRIVATE_RECEIPT"`. The receipt file must not exist and is created mode 0600 before external activity, as a replay lock. No production commands should be run during code review.

`--execute` verifies signature against build-pinned reviewer fingerprint, file/provenance/config digests, GPG decrypts in memory, checks complete account/OAuth row JSON against exact DB preimage in a read-only transaction, verifies count/owner/org/worker/email/inactive Outlook/version/no pending-active tasks and fifth fingerprint, refreshes permit/fence checks, invokes the service's read-only Graph validation and atomic single-row CAS, then reads back account row unchanged, OAuth sentinel/empty access token, task count and fifth fingerprint. A successful synced JSON receipt contains target ID, permit/binary/escrow hashes and `reconciled:true`; no secrets. An unsuccessful/missing readback or receipt sync means **manual reconciliation required**; do not blindly retry. No success claim from a dry-run, unsigned evidence, empty receipt, Graph GET alone or CAS result alone. Rollback remains a separate reviewed one-row operation as described in `outlook-app-only-conversion.md`.

Focused verification: `go test ./cmd/outlook-convert ./internal/app/email ./internal/repository` and `make lint`. GPG tests verify the captured permit bytes (including pathname replacement), pinned reviewer identity, and captured encrypted escrow bytes. The Graph fixture remains synthetic. For an actual isolated PostgreSQL CAS test, run `PRIMARY_DB=<disposable-local-URL> go run ./cmd/migrate` and `RECONNECT_TEST_DATABASE_URL=<same-disposable-local-URL> go test ./internal/repository -run TestReconnectRepositoryPostgres -count=1 -v`. That test creates and drops its own schema and covers one winning CAS, replay, wrong worker/email/owner/org, excluded fifth target, queued-task denial and inactive status. No production credentials, rows or tenant are required.

After Graph validation the runner rechecks the signed permit, bound grant/fence freshness, no-send window and actual fence expiry before the CAS; the write context expires at the earliest permit/no-send/fence deadline. Exact readback has a separate bounded context if the write deadline expires after committing. A rejected/uncertain write is not a retry authorization: manually reconcile the exact row first. These local tests and this document are not production execution evidence.
