# Outlook RETRY warning recovery (code-only, 2026-10-04)

Graph delta sync emits a mailbox-ID-scoped success event with the pass start only after Inbox **and** Junk complete without error. The consumer rejects unbounded (old-format) success events. The SQL resolves only unresolved `SERVER_UNREACHABLE` / `severity = 'WARNING'` / `resolve_method = 'RETRY'` rows for that mailbox with `task_id IS NULL` and occurrence before the completed pass began. Migration 000084 records the worker's warning occurrence time separately from DB insertion time. Repeated unresolved warnings refresh their occurrence time; a late or replayed success cannot erase a newer warning. Legacy warnings without occurrence time use their DB creation time conservatively. Send-specific rows with a task ID remain unresolved by app-only sync, even when they share this error code. A failed second folder cannot emit success. A generic app-token Graph 200, an account/tenant-wide probe, or a delta cursor is not recovery evidence. App-only sync success does **not** prove delegated auth is healthy. This change does not reactivate an inactive account, remove a warmup deny/quarantine, grant send permission, or resolve `AUTHENTICATION_FAILED` / `REAUTH` errors. Deploy the migration before the new producer/consumer; an old event lacking a pass start is rejected rather than used to clear warnings.
